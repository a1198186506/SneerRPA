# SneerRPA 原型

Windows 桌面 RPA 编辑器：Neutralinojs 6.7.0 + Python 3.11。

## 启动

本机依赖已安装，在 PowerShell 中运行：

```powershell
cd F:\test_pj
npm.cmd start
```

也可以运行 `powershell -ExecutionPolicy Bypass -File F:\test_pj\start.ps1`。
启动脚本会检查并补齐依赖，需要 Python 3.11+、Node.js 22+ 及网络。本次增加 OpenCV 与 NumPy，更新后建议先运行一次上述 start.ps1。

## 使用

1. 启动后进入项目首页。点击“新建项目”并输入名称开始编辑，或点击历史项目继续；也可通过顶部“项目 → 载入示例”创建窗体示例项目。引擎连接提示已隐藏，连接就绪后首页按钮可用。
2. 点击“运行流程”：程序启动自己的 WinForms 测试软件，依次获取窗口、激活、还原、等待输入框、填写中英文及特殊字符、点击确认、读取结果、打印日志、关闭窗口。
3. 点击左侧动作或拖入流程添加步骤；拖到步骤上半区插在前面，下半区插在后面，紫色提示线表示实际插入位置。步骤间箭头也可以接收拖入，主流程与 IF 分支均支持。拖拽已有步骤采用相同规则，也可以在右侧上移/下移。
4. 选择步骤，在右侧配置参数。右键节点可选择“删除节点”，IF 会连同其分支步骤删除；运行或使用定位工具期间禁止删除。菜单可按 Esc 或点击外部关闭。运行时可切换“运行日志 / 运行变量”；“停止”终止执行器，已经打开的目标软件仍保留，避免丢失业务数据。
5. 每个项目的流程及元素库自动保存到 `projectdata/projects/<项目ID>.json`。草稿允许暂时未填写目标元素或数值越界，但执行前会严格校验。等待顶部显示“已保存到本地”再退出；“项目 → 导出”仍可导出包含图片及控件素材的流程 JSON。

动作库和属性面板之间的分隔条可左右拖动，日志区上缘可上下拖动。动作库宽度限制为 200–420 px，属性面板 260–520 px，日志区高度 120–560 px；窗口较小时会进一步限制最大尺寸，保留编排区域。双击分隔条恢复该面板默认尺寸，分隔条获得焦点时也可用方向键调整，尺寸保存在界面本地存储中。

编排区右上角“放大编排区”会隐藏左右面板和底部日志区，让流程铺满顶部导航栏以下区域；点击“还原布局”或按 Esc 返回原布局。放大不改变流程内容，也不退出正在运行的流程。

启动时显示首页，历史项目按最近保存时间排序，展示名称、步骤数量及保存时间。点击历史项目直接载入保存的工作流；不会自动运行。

## 项目管理

- 顶部“新建 / 导入 / 导出 / 载入示例”收进“项目”菜单。编辑页选择“新建”先弹出确认框，取消继续编辑；确认返回首页，尚未自动保存的修改被丢弃，已保存内容保留在历史项目中。
- 首页“新建项目”要求输入 1–80 个字符的名称，不能仅为空格。创建后进入空白流程，并立即建立项目文件。同名项目通过独立 ID 区分，不会互相覆盖。
- “导入”将 JSON 工作流创建为独立项目，使用工作流名称；已有项目会先保存。导入和示例均保留现有历史项目。“导出”生成与旧版兼容的 schema_version=1 工作流，包含控件和图片素材，不依赖本机历史项目 ID。
- 编辑后的变化延迟约 650 ms 自动保存，保存请求按顺序执行；返回首页会取消尚未开始的自动保存，并等待已经开始的保存完成，防止不同项目的内容串写。项目文件使用临时文件替换，写入失败时保留之前保存的版本。
- 旧版 `projectdata/current-flow.json` 会在首次列出历史时迁移为一个项目，原文件保留；迁移标记为 `projectdata/projects/.legacy-migrated`，之后不会重复导入。损坏的项目或旧流程会在首页提示，保留原文件，其他项目仍可打开。“测试窗口（旧版）”已从动作库及添加步骤列表移除；历史 demo_window 流程仍可读取和执行。

## 导出工作流为 EXE

1. 在编辑页打开一个已经配置完整的流程，选择“项目 → 导出为 EXE”。空流程、运行中或定位工具使用中不能开始导出；其余参数在开始打包前严格校验。
2. 点击“选择文件夹…”指定保存位置，也可以填写绝对路径；输入 EXE 文件名称，`.exe` 后缀可省略。支持中文和空格，拒绝路径字符及 Windows 保留名称。同名文件已存在时要求改名，不会直接覆盖。
3. 点击“开始导出”，查看实时打包日志。首次打包可能需要几分钟，可点击“取消导出”结束打包进程及其子进程。成功后显示完整保存路径和文件大小，构建失败不会产生半成品 EXE。
4. 导出的是当前工作流快照及其控件/图片素材，使用 PyInstaller 打成单个 Windows x64 EXE，包含 Python、UIA/Win32、Pillow、OpenCV 和 Tk 运行界面。目标电脑无需安装 Python、Node.js 或 Neutralino。双击后点击“运行工作流”，界面显示运行状态、日志及停止按钮。

内置“Windows 窗体自动化示例”使用的 `tools/test-window.ps1` 会自动打包到 EXE 中，并从内部资源定位，因此移动 EXE 到其他文件夹仍可启动测试台。已有示例项目使用原来的相对路径或项目内绝对路径，也会在导出时自动转换，不修改原项目。此前导出的 EXE 需要重新导出才能获得此修复。

用户引用的其他目标软件、外部脚本、文档等不随 EXE 自动复制，需要在运行电脑准备；绝对路径也需保持可用。导出的程序从 EXE 所在文件夹解析普通相对路径。运行 RPA 仍需要交互桌面，窗口权限要求与编辑器一致。停止执行器会保留它启动的目标应用，避免关闭业务软件。启动的进程若异常退出，会明确报告退出码及路径/参数检查提示，避免只显示“未找到窗口”。

打包依赖已加入 `requirements.txt`，缺少依赖时运行 `powershell -ExecutionPolicy Bypass -File F:\test_pj\start.ps1` 安装并重启。EXE 体积包含完整 Python 与图像依赖，通常为数十 MB。

## 第一批窗体节点

| 节点 | 主要配置 |
| --- | --- |
| 运行或打开 | 浏览选择程序或文件、可选启动参数、输出进程变量；本地文档和 HTTP(S) 地址可调用系统默认应用打开 |
| 获取窗口对象 | 元素所属窗口 / 窗口变量 / 窗口条件三种来源，输出窗口变量 |
| 激活软件窗口 | 三种窗口来源，最小化时先还原 |
| 设置窗口状态 | 三种窗口来源、还原 / 最大化 / 最小化 |
| 点击元素 | 元素库条目、单击 / 双击 / 右击、控件接口或真实鼠标 |
| 填写输入框 | 元素、文本、是否清空、控件接口或真实键盘 |
| 等待元素 | 出现且可见 / 消失或隐藏、超时、结果变量、超时是否停止 |
| 获取元素信息 | 文本 / 值 / 常用属性 / 位置大小、输出变量 |
| 关闭软件窗口 | 三种窗口来源，预览目标窗口，发送正常关闭请求 |
| 鼠标点击 | 元素库 / 屏幕坐标，单击 / 双击 / 右击，支持实时捕获坐标 |
| 键盘输入 | 仅填写要输入的文本，发送到当前获得焦点的位置 |
| 以图找图 | 图片素材、全屏 / 指定窗口 / 框选区域、阈值、超时，输出匹配结果 |
| 设置变量 | bool / string / number / window，自定义值或引用已有变量，窗口还可直接定位获取 |
| IF 条件判断 | 变量与同类型变量或自定义值比较，嵌套“如果 / 否则”分支 |
| 判断窗体是否存在 | 三种窗口来源、等待超时、输出布尔结果 |
| 循环 | 自定义非负整数 / number 变量，循环体、序号、次数上限 |
| 跳出循环 | 结束当前最内层循环，继续执行循环后的步骤 |
| 继续循环 | 跳过当前最内层循环本轮的剩余步骤，进入下一轮 |

窗口节点统一提供“窗口获取方式”，新节点默认从元素库选择：

- **从元素库获取所属窗口**：选择任意已捕获的控件，操作的是它所属的整个窗口，不点击这个控件。使用保存的所属窗口条件定位，因此子控件暂时消失不影响窗口操作。右侧显示目标窗口名称；关闭节点明确显示将关闭整个窗口。
- **使用窗口变量**：填写先前步骤输出的窗口变量，例如 `main_window`。
- **按窗口条件查找**：填写标题及匹配方式；高级设置可补充类名、进程名、进程 ID、后端和超时，也可直接从当前窗口列表选择。

控件节点默认使用元素自身保存的窗口信息，不再要求先获取窗口变量。确需限定另一个窗口实例时，在“高级设置”填写“窗口变量（可选）”。旧流程保留原有窗口条件和变量含义，导入后自动补充获取方式，不需要手动重配。

“运行或打开”的“浏览程序或文件…”使用系统文件选择框；没有启动参数时保持 `[]`。从元素库关联启动/复用应用的组合能力尚未加入。

窗口变量填写名字，例如 `main_window`。文本可用 `${result_text}` 引用前面步骤的结果。获取窗口的进程 ID 可填写 `${app_process}`，限定为刚启动的进程，避免多实例时误选窗口。由系统关联程序打开的文件/网址可能复用已有进程，此时进程输出可能为 null，应改用标题等条件获取窗口。
参数数组按数组项直接传给程序，不拼接 shell 命令。需要运行 PowerShell 脚本时，显式选择 `powershell.exe` 并配置参数，参考示例。

## 鼠标点击与键盘输入

两个节点位于动作库的“鼠标键盘”分组。

- **鼠标点击 → 元素库元素**：选择已捕获元素，使用真实鼠标点击控件中心；也支持双击和右键。与“点击元素”的控件接口方式不同，该节点始终使用实际鼠标。
- **鼠标点击 → 屏幕坐标**：填写整数 X/Y，或者点击“实时捕获坐标…”。浮动提示实时显示当前坐标，移动鼠标后按 **F8** 确认，**Esc** 取消；也可以在参数面板点击“取消坐标捕获”。取消保留原坐标，60 秒未确认自动退出。左侧或上方副屏可使用负坐标，执行时会检查坐标是否位于当前显示器内。坐标相对屏幕而非窗口，目标窗口移动后需重新捕获。
- **鼠标点击 → 位置变量**：选择前面“以图找图”输出的 `image_match.center`。请先用 IF 判断 `image_match.found == true`，未找到时中心为空，执行器会拒绝点击。
- **键盘输入**：参数面板只填写“要输入的文本”，不选择窗口或元素。输入发送到当前获得焦点的位置，不会自动清空旧内容。推荐先用鼠标点击目标输入框，再接键盘输入节点。支持中文、表情和多行文本；换行发送回车，Tab 发送制表按键。`{ENTER}`、`+`、`^` 等按普通文字输入，不解析为快捷键；`${变量名}` 仍按流程的变量引用规则替换。

示例：鼠标点击（元素或坐标） → 键盘输入 → 鼠标点击（确认按钮）。

## 元素拾取与元素库

1. 打开要操作的目标软件，切换左侧“元素库 → 控件元素”，选择 UI Automation（优先）或 Win32。“图片素材”页签单独管理截图，两类页签显示各自数量，上方元素库显示总数。
2. 点击“拾取元素”，鼠标移到控件上查看紫色边框，按 **F8** 捕获，**Esc** 取消。60 秒未捕获会自动退出，也可在界面取消工具。
3. 编辑名称，点击“测试定位 / 高亮”，确认唯一定位成功，再保存。
4. 在点击、输入、等待和读取节点的“目标元素”中选择该元素。节点右侧也可直接拾取，捕获结果会绑定当前步骤。
5. 控件节点的“高级设置”里若填写窗口变量，元素会在该窗口内定位；留空则使用元素选择器中保存的窗口条件。两者后端必须一致。窗口节点则选择“从元素库获取所属窗口”，可直接复用同一个元素。

选择器保存窗口条件和控件属性路径，不保存运行句柄。UIA 优先使用 AutomationId 与控件类型，忽略 WinForms 动态类名和 UIA 运行期 control_id。多个匹配结果会报错，不默认操作第一个对象。名称或结构动态变化时，可手动修改 JSON（例如窗口标题改为包含/正则匹配）。Win32 控件 ID 或类名也可能随软件重启变化，需要按实际软件调整。

## 拾取图片与图片素材

进入“元素库 → 图片素材”，图片捕获按钮及图片列表与控件元素分开展示：

1. 点击“拾取图片”。桌面模式会临时隐藏编辑器，显示冻结的桌面截图。
2. 按住鼠标左键拖动框选目标，松开确认；支持反向拖动。至少框选 2 × 2 像素，**Esc** 取消，60 秒未操作自动退出。
3. 在图片预览中填写名称、查看原图尺寸与捕获位置，点击“保存名称”。也可“重新截取”，保留原素材 ID 和名称；取消重截保留旧图。
4. 图片卡片支持缩略图、预览、编辑与删除。图片数量计入元素库总数，图片不出现在控件选择器中，避免被窗口或控件节点误用。

图片保存原始 PNG 像素，包含宽高和捕获区域，支持虚拟桌面及负坐标。当前流程的 `images` 数组内嵌 PNG 内容，随本地保存、导出、导入完整迁移，不依赖临时截图路径；旧流程没有 images 字段时按空素材库处理。单图最多 8 MB，总图片内容最多 16 MB。

图片可以直接用于“以图找图”，原始捕获坐标仅作参考，实际位置由当前屏幕重新匹配。

控件节点面向目标软件公开的 UIA / Win32 控件；自绘界面可尝试图片模板匹配，目前没有 OCR。真实鼠标键盘、截图和拾取需要交互桌面；管理员权限软件通常需要本程序以匹配的权限运行。

## 以图找图

采用 OpenCV 模板匹配（TM_CCOEFF_NORMED），目标图片从图片素材库选择。

1. 先激活目标窗口，使目标区域可见。窗口范围仅限制截图位置，不能读取被遮挡或最小化窗口的后台画面。
2. 选择全屏、指定窗口变量或屏幕区域。区域可以填写坐标和宽高，也可“框选搜索区域…”。
3. 设置阈值（默认 0.9）和超时（默认 3 秒）；超时 0 表示只尝试一次。点击“测试找图”可预览匹配分数，并短暂高亮位置，测试最长等待 5 秒。指定窗口的单步测试要求窗口变量能从已配置的窗口定位步骤独立获取；依赖前面运行进程输出的条件可改用全屏 / 区域测试，或运行完整流程。
4. 高级设置支持灰度、有限多尺度搜索（0.8 / 0.9 / 1 / 1.1 / 1.25）和多个匹配时的处理。默认多个高分目标报错，可缩小范围或明确选择最高分。分数是相似度，不是识别概率。

输出 `image_match` 包含 `found`、`score`、左上角 `x/y`、`width/height`、中心 `center.x/center.y`。坐标统一为屏幕坐标，支持副屏负坐标。超时未找到返回 `found=false`，位置与中心为 null；图片损坏、窗口失效或多目标歧义会报错。纯色无纹理图片会要求重新截取。默认按原尺寸匹配，DPI、缩放、主题或内容变化可能需要重截模板；多尺度搜索不是任意比例识别。

推荐流程：获取窗口 → 激活窗口 → 以图找图 → IF `image_match.found == true` → 如果分支中鼠标点击 `image_match.center`。

## 变量和 IF 分支

- **设置变量**：填写变量名称和类型。bool 使用复选框，string 使用文本框，number 使用数值框；window 可从元素所属窗口、已有窗口变量或条件定位。选择“已有变量”时按值的实际类型复制，窗口保留运行期对象。自定义文本原样保存，包括 `${...}` 字样；不会求值 Python 表达式。同名变量允许更新，但不能改变类型。
- **IF 条件判断**：左侧选择前面步骤的 bool/string/number 变量；右侧可选已有变量或按类型输入。支持 `==`、`!=`，数字另支持 `>`、`>=`、`<`、`<=`。两侧类型必须一致，不把字符串数字或 bool 自动转成 number。
- **分支编辑**：在“如果 / 否则”区域拖入动作，或点击该区域底部“＋ 添加步骤”，在弹出的动作列表中搜索、选择，直接添加到当前位置。取消选择不会改变后续添加目标；点击左侧动作库始终添加到主流程末尾。支持嵌套、跨分支拖动及同分支上移/下移，删除 IF 会删除其子步骤。未选中的运行分支会显示灰色跳过状态。
- **变量作用域**：分支内可用进入该分支前的变量和本分支前面的输出。IF 后只能直接引用两个分支都保证赋值且类型一致的变量，或者进入 IF 前已有的变量。引用下拉框据此过滤，执行前再次校验，阻止引用后续步骤或可能未执行的赋值。
- **判断窗体是否存在**：支持元素所属窗口、窗口变量、条件查找。未找到或已关闭返回 false；找到返回 true。多个窗口匹配、无效参数及未定义变量会报错。超时默认 0，可在高级设置中配置等待窗口出现。

“运行变量”展示值和类型。文本输出节点可用 `${image_match.found}` 等点路径引用；窗口对象只在本次运行内有效，保存的是步骤配置。可导入 `resources/logic-flow.json` 体验不依赖图片的变量与嵌套分支示例。

## 固定次数循环

动作库“逻辑与变量”增加“循环 / 跳出循环 / 继续循环”。本版先支持固定次数，While 条件循环尚未加入。

1. 添加“循环”，选择“次数来源”：手动填写非负整数，或者选择前面步骤的 number 变量。bool、string 和窗口变量不会出现在次数下拉框中。
2. 执行时仍会检查变量实际值：0 次直接跳过，负数、小数、非有限数字或超过上限时报错，不自动取整或转换类型。循环次数上限默认 1000，可在高级设置中调整，最大 10000；自定义次数超过上限会在流程启动前拦截，变量次数在进入循环体前检查。
3. 次数在每次进入该循环时只读取一次。例如进入时 count=5，即使循环体修改 count，本次仍最多执行 5 轮；Break 可以提前结束。嵌套循环每次进入时会重新读取自己的次数。
4. 拖入“循环体”，或点击其底部“＋ 添加步骤”，从弹出列表中搜索、选择动作。内部支持 IF、嵌套循环、节点前后插入、跨容器拖动和右键删除。删除循环会同时删除其所有子步骤。
5. 序号从 1 开始，默认变量名 loop_index；新增嵌套循环会避开已使用的序号/输出名称，例如 loop_index_2，也可手动改名。活动的嵌套循环不能使用相同序号名。在循环体内的 IF 和文本中可引用序号，日志示例：`第 ${loop_index} 次`。
6. “跳出循环”只结束最近一层循环，“继续循环”只跳过最近一层循环的当前轮。二者可放在循环体内的 IF 分支中，不能单独放在主流程。被跳过的步骤显示灰色，下一轮会重新更新步骤状态；循环节点显示当前轮数。现有“停止”按钮也能终止循环中的执行器。

循环前已有的变量可在循环内更新。只在循环内创建的变量（包括序号），循环后不保证存在，因此后续引用下拉框不会提供；若需要在循环后使用结果，应在循环前先用“设置变量”初始化它，再在循环体中更新。

可导入 `resources/loop-flow.json`：次数取自 number 变量 repeat_count；第二轮 Continue，第四轮 Break，随后输出“循环已结束”。不操作外部软件，可直接体验执行轨迹。

## 结构

- `resources/`：编辑界面、共享动作定义 `actions.json`、完整窗体示例。
- `extensions/backend.py`：官方 Extensions 协议、消息及执行进程管理。
- `extensions/projects.py`：命名项目存储、历史列表、原子保存及旧流程迁移。
- `extensions/exe_export.py`：PyInstaller 构建、输出路径校验及原子发布。
- `extensions/standalone_runner.py`：导出 EXE 的运行窗口、独立执行器及停止处理。
- `extensions/runtime_resources.py`：内置资源在源码及独立 EXE 中的安全定位。
- `extensions/worker.py`：独立流程执行器。
- `extensions/automation.py`：窗口选择器、元素路径定位、变量上下文与动作实现。
- `extensions/tools.py`：独立元素拾取、实时坐标捕获、窗口枚举和定位测试进程。
- `extensions/image_capture.py`：冻结桌面、框选区域与取消处理。
- `extensions/image_assets.py`：原始 PNG 编码、可迁移图片数据与内容校验。
- `extensions/vision.py`：桌面区域截图、OpenCV 模板与多尺度匹配。
- `extensions/values.py`、`resources/flow-model.js`：类型、变量引用、比较规则及编辑器分支作用域。
- `resources/editor-layout.js`：面板拖动、尺寸限制及编排区放大还原。
- `extensions/validation.py`：执行前校验、草稿及选择器校验。
- `extensions/parameters.py`：条件参数、统一默认值和旧流程兼容。
- `tools/test-window.ps1`：自有 WinForms 测试软件。
- `neutralino.config.json`：窗口、权限及 Python 扩展启动配置。
- `tests/smoke.cjs`：真实 Neutralino 核心 + Python + 浏览器端到端测试。

前端通过 `extensions.dispatch` 发送 command，Python 通过 `app.broadcast` 回传 rpa 事件。命令带 request_id，执行事件带 run_id 与 node_id。流程保持 schema_version=1，IF 步骤包含 then_steps / else_steps 数组，循环步骤包含 body_steps 数组。容器最多嵌套 16 层，总步骤最多 1000 个。Python 扩展常驻，每次运行创建独立执行器；连接关闭时清理执行器。

# Windows 安装包

运行 `npm run build:installer` 构建完整的 Windows x64 安装包，输出为
`dist/SneerRPA-Setup-0.1.0-x64.exe`。此命令使用当前虚拟环境的依赖和对应的
Python 基础安装，包含编辑器、Python、OpenCV、窗口自动化、Tk 和 PyInstaller，
目标电脑无需安装 Python、Node.js，也不需要联网下载运行依赖。

构建前在 `.tmp/installer-tools` 准备 Windows NSIS 编译器（含其完整目录）和
`MicrosoftEdgeWebView2RuntimeInstallerX64.exe`，后者从 Microsoft 官方 WebView2
页面下载 x64 Evergreen Standalone Installer。构建脚本会验证 Microsoft 数字签名。
本次构建使用 electron-builder-binaries 分发的 NSIS 3.0.4.1 Windows 编译器。
安装程序会检测 WebView2，缺失时使用包内离线安装程序安装。

默认安装位置：`%LOCALAPPDATA%\Programs\SneerRPA`，无需管理员权限。
安装版项目位置：`%LOCALAPPDATA%\SneerRPA\projects`，卸载或升级会保留。
安装包不携带开发目录中的历史项目，原有工作流可通过 JSON 导出、导入迁移。
安装版使用包内 Python，可继续从项目菜单导出独立的工作流 EXE。

构建脚本每次使用独立、干净的暂存目录，避免将 `.tmp` 测试数据、历史项目或
Neutralino 连接凭据打入发布文件。开发用 `npm run build` 仍仅构建 Neutralino 壳。

安装验证：可先用 `/S /TESTMODE /D=绝对路径` 静默安装到独立测试目录
（`/D` 必须在最后，此模式不创建快捷方式和卸载注册表项），然后执行
`node tests/installer-smoke.cjs 绝对安装路径`，验证真实编辑器、示例、项目保存、
工作流 EXE 导出与导出 EXE 执行。正常安装请直接双击安装程序。
